我建议你最终采用：三维几何融合 + 多视角特征保留 + 匹配时概率融合（Geometry-first, Feature-preserving Late Fusion）。

这比简单的归一化加权平均更适合 MARCO，也更符合你提出的全部要求：

- 一个三维点只有 A 相机能看到：直接使用 A 的 MARCO descriptor，完全不需要融合。
- 一个三维点能被 A、B 同时看到：保留两份 descriptor，而不是强行平均成一份。
- 演示视频只有一个视角：使用演示的单视角 descriptor，直接与目标三维点上的多视角 descriptor 集合匹配。
- 不选择与演示最相似的运行期摄像头，也不分别生成两套区域迁移结果。
- 最终只在融合后的三维场景里生成候选区域，并通过区域几何和结构关系选择结果。MARCO 的 `forward_backbone()` 可以提取密集特征，而公开代码在计算相似度时实际上使用的是原始特征向量点积，并没有在 `sample_descriptors_w_sim()` 内部先做 L2 normalization。

所以，如果你希望单视角情况下完整保留原有 MARCO 的匹配行为，最终设计也应该考虑这一点，而不是默认把所有特征都改成 cosine similarity。

## 1. 为什么我不建议直接平均 MARCO 特征？

考虑同一个真实三维点 \(p\)，它在两个视角下的描述子分别是：

\[ f_A(p),\qquad f_B(p) \]

传统方法先做：

\[ \bar f(p)=\operatorname{Normalize} \left(w_Af_A(p)+w_Bf_B(p)\right) \]

然后使用 \(\bar f(p)\) 匹配演示中的描述子 \(f_D\)。

这个方法实际上包含一个较强假设：

同一个三维点在不同视角下的 MARCO 描述子，应当是同一个潜在特征加上随机扰动。

如果该假设成立，加权平均可能有效。

但 MARCO 是为二维图像之间的语义对应设计的。它具有跨视角泛化能力，却没有被明确训练成一个严格视角不变的三维特征编码器。

因此，同一个三维表面的描述子可能因视角产生具有方向性的系统偏差，而不只是随机噪声。

### 一个数学反例

假设描述子已经归一化，并且：

\[ f_D=f_A= \begin{bmatrix}1\\0\end{bmatrix}, \qquad f_B= \begin{bmatrix}0\\1\end{bmatrix} \]

这里 \(f_D\) 是演示描述子，\(f_A,f_B\) 是目标物体同一三维点在两个视角下的描述子。

假设等权融合：

\[ \bar f= \frac{f_A+f_B}{\|f_A+f_B\|_2} = \frac{1}{\sqrt{2}} \begin{bmatrix}1\\1\end{bmatrix} \]

则融合后的余弦相似度为：

\[ f_D^\top\bar f=\frac{1}{\sqrt{2}} \]

但使用 A 视角原始描述子时：

\[ f_D^\top f_A=1 \]

也就是说，原本完全正确的特征对应，在平均之后反而变差了。

更危险的是，一个错误候选点的 descriptor 可能恰好更接近平均向量，导致错误候选超过正确候选。

所以我的设计原则是：

融合三维位置，但不要求融合后的每个三维点只能有一个 descriptor。

## 2. 最终的数据表示：一个三维点，可以包含多份特征

我建议不要把融合结果定义为传统的：

\[ \mathcal P=\{(p_i,\bar f_i)\} \]

而是定义为：

\[ \boxed{ \mathcal P= \left\{ \left(p_i,n_i,\Sigma_i,\mathcal O_i\right) \right\}_{i=1}^{N} } \]

其中：

- \(p_i\in\mathbb R^3\)：世界坐标系中的表面点。
- \(n_i\)：该点的表面法向。
- \(\Sigma_i\)：该点的几何位置不确定性。
- \(\mathcal O_i\)：所有有效观测该表面点的相机特征集合。
- \(N\)：融合后表面点的总数。

每个点的观测集合为：

\[ \mathcal O_i= \left\{ (f_{iv},w_{iv},v)\mid v\in\mathcal V_i \right\} \]

这里：

- \(f_{iv}\)：相机 \(v\) 对该三维点提取的 MARCO descriptor。
- \(w_{iv}\)：该观测的几何可靠性。
- \(\mathcal V_i\)：实际能够观测该点的相机集合。
- \(v\)：相机标识，只用于管理观测，不用于决定哪个相机更接近演示。

具体存储结果可以是：

| 表面点  | 三维几何     | 可用特征         |
| ------- | ------------ | ---------------- |
| \(p_1\) | XYZ + normal | MARCO-A          |
| \(p_2\) | XYZ + normal | MARCO-B          |
| \(p_3\) | XYZ + normal | MARCO-A、MARCO-B |
| \(p_4\) | XYZ + normal | MARCO-A、MARCO-B |

无论有几个 descriptor，\(p_3\) 都只是一处物理表面，不是两个独立点。

这很重要。两个相机观察同一个表面点，不应该使该区域在后续配准中获得双倍的点数权重。

### 几何融合具体如何处理？

首先将两个相机的点云变换到统一的世界坐标系。

我建议使用 voxel / surfel fusion，而不是简单拼接点云。

在确认两个观测来自同一物理表面后，可以根据深度测量的不确定性融合三维位置：

\[ \Sigma^{-1}=\Sigma_A^{-1}+\Sigma_B^{-1} \]

\[ p=\Sigma\left( \Sigma_A^{-1}p_A+ \Sigma_B^{-1}p_B \right) \]

其中：

- \(p_A,p_B\)：两个相机对同一物理表面点的测量。
- \(\Sigma_A,\Sigma_B\)：对应测量的三维协方差矩阵。
- \(p,\Sigma\)：融合后的几何位置与协方差。

这是两次独立高斯测量下的加权最小二乘解。实际使用时还需要考虑相机标定误差的相关性。

但不能只凭两个点的欧氏距离足够近，就认定它们是同一个表面点。

特别是 shelf 的薄层板、drawer 的内壁与外壁，可能出现空间距离很近但属于不同物理表面的情况。因此还需要检查法向一致性，以及它们是否属于同一连续表面。

几何融合完成后，MARCO 特征仍按各自相机保留。

## 3. 哪些相机特征应该被加入同一个三维点？

这里必须做严格的可见性验证。

对于三维点 \(p\)，将其投影到相机 \(v\)：

\[ u_v=\pi_v(p) \]

然后计算：

\[ r_v(p)=z_v(p)-D_v(u_v) \]

其中：

- \(\pi_v\)：相机 \(v\) 的投影函数。
- \(u_v\)：投影后的图像像素位置。
- \(z_v(p)\)：该点在相机坐标系下的深度。
- \(D_v(u_v)\)：深度图在该像素位置的实测深度。
- \(r_v(p)\)：深度重投影残差。

只有满足：

\[ |r_v(p)|<\epsilon_z(z_v) \]

并且处于有效物体 mask 内、未被遮挡、深度有效时，才读取：

\[ f_v(p)=\operatorname{BilinearSample}(F_v,u_v) \]

这里 \(\epsilon_z(z_v)\) 是根据深度相机噪声和标定精度确定的距离容差。

这一步有两个容易忽略的工程细节。

第一，MARCO 特征图和原图的分辨率不同。 需要正确记录图像 resize、crop、padding 的坐标变换，不能直接拿原始相机像素坐标去采样特征图。

第二，深度不连续边界的特征不一定可靠。 MARCO 的上采样提高了特征空间分辨率，但不能保证卷积特征在物体轮廓、相邻薄表面处完全没有混合。建议对这些位置降低置信度。

对于有效观测，可以定义几何可靠性：

\[ w_v(p)= c_{\mathrm{mask}} \exp\left( -\frac{r_v(p)^2}{2\sigma_z^2} \right) \left[\max(0,n(p)^\top d_v(p))\right]^\gamma \]

其中：

- \(c_{\mathrm{mask}}\in[0,1]\)：物体分割置信度。
- \(\sigma_z\)：当前距离下的深度噪声标准差。
- \(n(p)\)：表面朝外的单位法向。
- \(d_v(p)\)：从表面点指向相机的单位向量。
- \(\gamma\geq0\)：控制斜视角观测降权程度的参数。
- \(w_v(p)\)：最终观测可靠性。

这个权重只表达几何测量是否可靠，不表达该相机是否与演示视角接近。

如果 A 能看见，B 被遮挡：

\[ \mathcal O(p)=\{(f_A,w_A,A)\} \]

不会给 B 添加零向量，更不会将缺失的 B 当作不匹配证据。

这是我建议作为最终版本采用的可见性处理原则。

## 4. 核心设计：用 Log-Sum-Exp 融合匹配证据，而不是平均特征

现在进入真正重要的部分。

演示视频只有一个视角。假设离线已经提取了一个交互区域，其三维点和 MARCO 特征为：

\[ \mathcal R_D=\{(x_i,f_i^D)\}_{i=1}^{M} \]

其中：

- \(x_i\)：演示交互区域的第 \(i\) 个三维点。
- \(f_i^D\)：该点的单视角 MARCO descriptor。
- \(M\)：演示交互区域的采样点数量。

目标场景中某个候选三维点为 \(p_j\)。

它可能拥有一份或两份 MARCO descriptor：

\[ \mathcal O_j=\{f_{j1},\ldots,f_{jK_j}\} \]

\(K_j\) 是这个三维点的有效观测数量，在双相机设置中为 1 或 2。

### 4.1 先保留 MARCO 原本的匹配分数

根据官方实现，使用：

\[ s_{ijv}=(f_i^D)^\top f_{jv} \]

其中 \(s_{ijv}\) 是演示点 \(i\) 与目标点 \(j\) 的第 \(v\) 个观测描述子之间的原始点积相似度。

这里暂时不增加 L2 归一化，以保证和 MARCO 原始匹配计算兼容。

然后，根据刚才计算的几何可靠性，把权重归一化：

\[ \pi_{jv}= \frac{w_{jv}} {\sum_{k\in\mathcal V_j}w_{jk}} \]

其中 \(\pi_{jv}\) 表示目标点 \(j\) 的第 \(v\) 个观测所占的权重，所有有效观测的权重之和为 1。

### 4.2 我建议采用的融合公式

\[ \boxed{ S_{ij}= \tau\log \left( \sum_{v\in\mathcal V_j} \pi_{jv} \exp\left(\frac{s_{ijv}}{\tau}\right) \right) } \]

其中：

- \(S_{ij}\)：最终在统一三维点云中使用的匹配分数。
- \(s_{ijv}\)：单个相机观测与演示 descriptor 的 MARCO 点积。
- \(\pi_{jv}\)：该相机观测的归一化几何可靠性。
- \(\tau>0\)：控制不同相机匹配证据聚合方式的温度参数。

这个公式可以理解成：把相机视角当成一个未观测的潜在变量，汇总来自不同视角的匹配证据。

如果把每个视角的特征点积经指数变换视为一种未校准的匹配似然，这个式子就是对潜在观测视角的边缘化。需要说明，MARCO 原始点积没有经过概率校准，所以 \(S_{ij}\) 首先是一个匹配评分，而不应直接当作真实后验概率。

### 4.3 为什么这个公式适合你的需求？

它有四个特别有用的性质。

性质一：只有一个相机可见时，严格退化为原始 MARCO 匹配。

如果只存在 A：

\[ S_{ij}= \tau\log\left( \exp(s_{ijA}/\tau) \right) =s_{ijA} \]

没有任何融合损失。

这正符合你希望的“只看见一个视角就按原方式处理”。这里严格保留的是单点描述子点积分数；后续三维区域配准仍然是你自己的系统，而不是 MARCO 原版二维 soft-argmax。

性质二：两个相机都得到相同匹配分数时，不会产生双倍奖励。

如果：

\[ s_{ijA}=s_{ijB}=s \]

那么：

\[ S_{ij}=s \]

因为 \(\pi_{jA}+\pi_{jB}=1\)。

也就是说，增加一个相机不会因为多了一份观测，就人为提高某个点的匹配分数。

性质三：不会把两个描述子平均成不存在的中间特征。

这个公式满足：

\[ \min_v s_{ijv} \leq S_{ij}\leq \max_v s_{ijv} \]

它在相似度空间汇总证据，而不是在特征空间制造一份新的 descriptor。

性质四：可以连续控制对视角差异的容忍程度。

当温度趋近于零：

\[ \lim_{\tau\to0^+}S_{ij} = \max_v s_{ijv} \]

它接近“只要存在一个高度匹配的有效观测，就允许这个三维点成为候选”。

当温度不断增大：

\[ \lim_{\tau\to\infty}S_{ij} = \sum_v\pi_{jv}s_{ijv} \]

它逐渐接近对多个视角的匹配分数求加权均值。

所以温度实际上控制了：

更重视最有利视角，还是更重视多视角整体表现。

我不建议直接令 \(\tau\) 无限接近零，因为那会退化为单视角最大值匹配，容易让某个视角偶然产生的高分错误对应通过。

更合理的做法是在有标注的开发/验证数据上校准一个固定温度，在线运行时不需要 GT，也不需要动态选择相机。

### 4.4 这算不算隐式选相机？

它确实会给不同相机的特征分数赋予不同贡献。

对 \(S_{ij}\) 求导：

\[ \frac{\partial S_{ij}}{\partial s_{ijv}} = \frac{ \pi_{jv}\exp(s_{ijv}/\tau) }{ \sum_k\pi_{jk}\exp(s_{ijk}/\tau) } \]

这个导数可以解释为第 \(v\) 个观测对当前匹配分数的软贡献。

但这不是你反对的 camera selection：

- 没有判断整个演示更接近左相机还是右相机。
- 没有先得到左相机的放置区域，再得到右相机的放置区域。
- 没有在两个独立结果之间投票。
- 所有候选始终属于同一个三维坐标系。

只是在计算某一个物理表面的相似度时，允许不同视角提供不同强度的外观证据。

我认为这是合理且必要的。

## 5. 但是，仅仅采用这个公式，仍然不够防止错匹配

这是最终方案中必须明确的一点。

假设多层 shelf 有两个候选区域：

- 第二层是演示真正指定的目标。
- 第三层是错误目标。

即使采用 Log-Sum-Exp，两层也可能因为 MARCO 特征相似而同时获得很高的分数。

特别是第三层只要有一个视角产生较高相似度，就有可能成为候选。

所以概率式特征融合负责跨视角兼容，不能同时承担区域身份判定的全部责任。

我建议接下来保留你已经实现的区域迁移机制，但把它的输入替换为统一的三维匹配证据。

### 不要只用一个 descriptor 查询整个场景

既然你离线提取的是交互区域，而不是 FMimic 的单个 keypoint，就没有必要只拿区域中心的一个 MARCO descriptor 匹配。

建议对演示交互区域进行空间均匀采样，保留多个查询点：

\[ \mathcal Q= \{(x_i,f_i^D)\}_{i=1}^{M} \]

这些点既提供 MARCO 特征，也保留彼此之间的三维空间关系。

对于每个演示点，使用上面的 \(S_{ij}\) 在统一目标点云中检索若干候选。

接下来不应该立刻选相似度最大的对应点，而是寻找能够让多个演示点共同形成一致的三维区域对应关系的假设。

这比从一个点恢复目标区域可靠得多。

### 使用区域级联合评分，而不是逐点贪心匹配

假设候选区域为 \(\mathcal R_h\)，其从演示到目标的空间对齐变换为 \(T_h\)。

我建议的区域评分是：

\[ \boxed{ Q(h)= S_{\mathrm{appearance}}(h) -\lambda_g E_{\mathrm{geometry}}(h) -\lambda_c E_{\mathrm{context}}(h) } \]

其中：

- \(S_{\mathrm{appearance}}(h)\)：演示区域与候选区域之间，经过多视角融合后的 MARCO 匹配分数，可以对经过几何配准后的对应点使用截尾平均。
- \(E_{\mathrm{geometry}}(h)\)：区域三维几何不一致程度，包括点到面距离、法向差异、边界及局部形状。
- \(E_{\mathrm{context}}(h)\)：候选区域与演示区域的整体结构关系差异。
- \(\lambda_g,\lambda_c\)：两种一致性约束的权重。

其中 \(T_h\) 用于将演示区域点映射到新场景的候选区域。当物体实例尺寸不同时，不应强行要求整个物体保持完全刚性的尺寸对应；可以在局部接触面上配准，再检查归一化空间位置和结构关系。

我会把这三项的职责严格分开。

| 约束                | 主要解决什么                           |
| ------------------- | -------------------------------------- |
| 多视角 MARCO 相似度 | 语义和局部外观是否对应                 |
| 区域三维几何一致性  | 是否为同类表面、是否形成一致的区域映射 |
| 物体结构上下文      | 是否为演示指定的层板、侧面或功能位置   |

对于你关心的多层 shelf，第三项尤其重要。

例如，演示选的是第二层 shelf，那么只检查平面法向、长宽及 MARCO 相似度不够。系统应该保留该层与相邻层板、整体架子结构之间的关系。

但这不意味着要强制每个任务都有专用的层板检测器。如果你已有的区域迁移方法能利用整体几何对应保留层级，就直接使用原来的方法即可。

### 这里还需要一个拒绝错误匹配的条件

假设两个候选区域最终都得到合理的 \(Q(h)\)。

不能仅因为其中一个略高，就声称它必然正确。

可以设置：

\[ Q(h_1)-Q(h_2)>\delta \]

其中：

- \(h_1,h_2\)：评分最高和第二高的两个不同区域候选；
- \(Q\)：上述统一评分；
- \(\delta\)：在验证集上确定的最低可接受区分度。

同时要求几何内点比例和有效匹配覆盖率达到最低标准。

如果这些条件不满足，系统应将结果标为有歧义，而不是虚构高置信度。

这并不意味着一定要人工提供对应点。它只是让感知系统知道何时没有足够证据。

如果两个区域在所有已观测视觉、几何及上下文信息上完全对称，那么没有 GT 的情况下，任何融合方法都无法保证选出演示真正指定的那个。

多视角融合增加了信息，但不能创造不存在的区分信息。

## 6. 最终系统应该如何组织？

我建议你直接实现下面这一条流水线。

```
演示 RGB-D(单视角 MARCO 特征 + 已提取的交互区域)  + 运行期 RGB-D (左、右视角 MARCO 特征 + 深度)
↓
Unified 3D Observation Map(一个表面点 + 法向 + 每个有效视角的独立 descriptor)
↓
Late Feature Fusion(单视角原始点积 / 双视角加权 Log-Sum-Exp)
↓
Region-level 3D Correspondence(区域内多点匹配 + 几何配准 + 结构上下文检查)
↓
Transferred Interaction Region(从迁移区域恢复交互 frame，继续原有 skill 执行流程)
```

对于不同可见性情况，处理规则如下：

| 情况                          | 最终处理                                       |
| ----------------------------- | ---------------------------------------------- |
| 只有 A 可见                   | 原始 MARCO-A 点积分数                          |
| 只有 B 可见                   | 原始 MARCO-B 点积分数                          |
| A、B 均可见，描述子一致       | 两份特征参与统一评分，结果不因相机数量翻倍     |
| A、B 均可见，描述子差异较大   | 保留两份特征，用 Log-Sum-Exp 汇总，不强行平均  |
| A、B 的深度无法对齐到同一表面 | 不融合为一个表面点，先判定几何观测是否有效     |
| 两个不同的目标区域都获得高分  | 用多点几何与结构关系验证；仍无法区分则报告歧义 |

对于只有一个视角观测的点，不要因为它只有一次观测就自动降低 MARCO 匹配分数。单视角可见性是正常现象，不是错误证据。

多视角数量可以用于估计几何可靠性，但不应该被当成语义正确性的简单投票数。

## 7. 如果作为最终方案，我要求它通过哪些验证？

我认为架构可以现在就定下来，但有三个核心性质必须通过实验确认。

第一，单视角退化性质。 将 B 相机输入完全移除，输出的单点 MARCO 匹配分数应该与原来使用 A 的实现一致。这样你不会因为引入双视角系统破坏已经有效的单视角结果。

第二，互补视角收益。 两个相机观察同一个对象的不同侧面时，融合后的有效区域覆盖应该增加。特别要验证一部分目标只在 A 可见、另一部分只在 B 可见的情况。

第三，重复区域判别。 用多层 shelf，以及具有相似内壁和底面的 drawer，验证最终迁移的是正确的结构区域，而不是仅仅得到一个几何上自洽的匹配。

此外，Log-Sum-Exp 的温度需要校准。建议固定 MARCO checkpoint 与图像预处理，比较不同温度下正确区域的匹配分数、错误候选分数和区域迁移准确率。原始 MARCO 使用点积，若不同相机的描述子范数分布存在明显偏移，还需要检查特征范数校准，避免某个相机仅因为向量模长较大而占优。是否切换为 cosine similarity，也应在开发集验证，不能未经测试就视为与原始 MARCO 等价。

## 我的最终建议

我会确定这一套设计：

\[ \boxed{ \text{3D Geometry Fusion} + \text{Per-view Descriptor Preservation} + \text{Late Evidence Marginalization} + \text{Region-level Geometric Verification} } \]

它的核心不是让两个 MARCO descriptor 变得相同，而是承认同一个三维点在不同视角下可以具有不同的视觉表征，同时确保这些表征只对应一个物理表面和一个最终交互区域。

这样，双视角为你提供的是更完整的三维观测和更丰富的匹配证据，而不是两个需要二选一的独立预测器。

不过我不想把它说成已经被证明最优。这是一套数学性质明确、可以直接实现且不需要额外训练融合网络的最终架构建议；Log-Sum-Exp 相比特征平均的实际收益，还必须在 MARCO 和你的交互区域数据上验证。

最值得保留的设计决策是：不要过早把多视角描述子压缩成单一向量。先融合几何，再融合匹配证据，把最终判断留给整个交互区域的三维对应关系。
