# Multi-view Grounding：最终方案的合理性与验证

我的判断是：应该在运行期联合使用左右两个 RGB-D 视角，而且这应该成为交互区域迁移的正式设计，而不是一种失败后的补救策略。

但你最后给出的定义比“直接融合左右 MARCO 特征”更合理：

> Multi-view Grounding：以源单视角示教为条件，同时利用目标左右相机的特征对应、三维几何和可见性证据，在统一的三维坐标空间中确定交互参考位置。

这意味着我们保留单视角示教得到的 Object-relative Descriptor，不为多视角重新训练表示，也不把左右 MARCO 特征平均成一个新向量。

真正融合的是针对同一个三维交互位置的证据，而不是特征本身。

我核对了 [D³Fields](https://proceedings.mlr.press/v270/wang25b.html)：它把多个视角的二维视觉基础模型特征投影并融合成三维描述子场。它能作为“三维空间中整合多个视角观测”的研究依据，但我们不需要复制其特征场构造方式。

## 1. 为什么 Multi-view Grounding 在数学上合理？

设：

- \(D_s\)：源单视角示教构造的物体相对关系描述子。
- \(\mathbf x\)：目标物体上的候选交互参考位置。
- \(O_L,O_R\)：左、右 RGB-D 观测及其 MARCO 对应关系。

我们想估计的是：

\[ \boxed{ p(\mathbf x\mid D_s,O_L,O_R) } \]

不是分别估计左侧位置和右侧位置后选一个。

在两侧观测给定真实位置后条件独立的理想情况下，可以写成：

\[ p(\mathbf x\mid D_s,O_L,O_R) \propto p(\mathbf x\mid D_s) p(O_L\mid\mathbf x,D_s) p(O_R\mid\mathbf x,D_s) \]

这里：

- \(p(\mathbf x\mid D_s)\) 表示源交互关系对目标位置的先验。
- 两个似然项分别描述左、右相机的观测对候选位置的支持程度。

这带来一个重要结论：

\[ H(X\mid D_s,O_L,O_R) \leq H(X\mid D_s,O_R) \]

\(H\) 表示条件熵，\(X\) 是未知交互位置。增加左侧观测，在信息论意义上不会增加对位置的最优推断不确定性。

但必须指出：信息增加不保证某个具体算法的预测正确率一定提升。 MARCO 的左右错误匹配可能高度相关，也可能存在结构化假对应；未经校准的评分直接相乘，反而会强化错误结论。

所以正式方案必须同时处理三件事：

1. 两个视角提供互补证据。
2. 同一个源 Anchor 被两侧观察时不能无条件重复计票。
3. 某个视角的对应不可靠时，它可以只提供几何或遮挡信息，而不必强行提供特征匹配证据。

这正是我认为 Multi-view Grounding 比简单的 View Selection 更有潜力的原因。

## 2. 我已经实际运行了联合 Grounding 仿真

为了不把理论讨论当作实验结果，我写了一份可复现的 Python 仿真。它包含 Shelf 和打开的 Drawer，两台目标相机的针孔投影和深度遮挡、源右侧单视角点云，以及有正确和错误对应的 MARCO-like 匹配输入。

重要限制：这里使用的是模拟的 MARCO-like 对应点，不是真实 MARCO 网络输出。 我没有你的实际 RGB-D 数据和 MARCO 特征缓存，也没有在这次实验中运行 MARCO 权重。因此这个实验验证的是多视角推理机制在受控几何和对应错误下是否可行，而不是证明真实机器人上的成功率。

实验设定：

- 8 组场景条件，每组 8 个随机试验，总共 64 次。
- 包含整体 1.25 倍缩放、非均匀尺寸变化、目标右侧遮挡、左侧错误对应和重复结构。
- 源点云只包含右侧相机实际可见的点，交互参考位置来自源可见区域。
- 目标左右相机的对应关系分别产生，最终在三维世界坐标中推理。
- 以参考点三维误差小于 75 mm 作为这次仿真的成功判据。

### 实际运行结果

| 方法                    | 定位成功率 | 成功输出的覆盖率 | 定位模块耗时中位数 |
| ----------------------- | ---------- | ---------------- | ------------------ |
| 仅右侧                  | 57.8%      | 100%             | 122.2 ms           |
| 左右二选一              | 93.8%      | 100%             | 168.7 ms           |
| 左右对应直接合并        | 92.2%      | 100%             | 255.3 ms           |
| 多视角距离关系投票      | 89.1%      | 100%             | 272.2 ms           |
| 多视角鲁棒仿射定位      | 87.5%      | 87.5%            | 10.2 ms            |
| 鲁棒仿射 + 关系定位回退 | 98.4%      | 100%             | 10.4 ms            |

上表是这 64 次合成试验的实测值，而非真实场景性能；耗时仅计几何定位核心，不含 SAM、MARCO 推理、图像传输和完整放置可行性检查。

### 结果反而纠正了一个直觉

简单地把两个视角的几何关系分数加在一起，并不一定比选择其中一个视角更好。

在这次测试中，纯多视角距离投票成功率为 89.1%，低于左右二选一的 93.8%。当 Drawer 非均匀变宽，同时某个视角产生大量错误对应时，统一尺度的距离关系会出现系统性误差。

但是，多视角鲁棒仿射定位在尺寸变化下表现很好；它失效的主要情况，是遮挡过强或缺少足够稳定的三维对应。用关系定位作为备用假设，而不是把两种分数简单相加，可以覆盖两者不同的失败类型。

所以我不建议把最终算法设计成一个简单的 Multi-view Descriptor Similarity Field。

更合理的是：多视角对应联合产生几何定位假设，跨视角可见性和接触几何验证这些假设，最后恢复一个交互参考位置及其不确定性。

这些结果支持继续采用 Multi-view Grounding，但不支持“视角越多、分数直接相加就一定越好”的假设。

## 3. 我建议正式采用的完整系统结构

```
Source Demonstration（仅右侧）：SAM 点云、交互中心、接触法向、MARCO Anchors、相对关系
↓
Target Left + Target Right ：MARCO 对应、RGB-D、可见性
↓
3D Correspondence Association：统一机器人坐标、双视角独立匹配、逐 Anchor 一致性检查
↓
Sim(3) Hypotheses + Bounded Affine Hypotheses +  Relational Hypotheses
↓
Joint Grounding & Hypothesis Verification：对应一致性、可见性、接触表面、模型复杂度、不确定性
↓
Interaction Reference + Metric Placement Sampling
↓
输出可靠参考位置
```

这里有四个必须从系统设计开始就考虑的问题。

### A. 左右匹配必须在统一三维坐标中建立联系

源 MARCO Anchor 为 \(\mathbf a_i\)。假设左右各自匹配到了目标点 \(\mathbf b_{iL},\mathbf b_{iR}\)。

通过标定得到的相机外参，将两者都变换到世界坐标：

\[ \mathbf b_{iv}^W= T_{WC_v}\operatorname{Backproject} (\mathbf u_{iv},d_v,K_v) \]

其中 \(v\in\{L,R\}\)，\(T_{WC_v}\) 是相机到世界坐标的刚体变换，\(\mathbf u_{iv}\) 是 MARCO 匹配像素，\(d_v\) 是该像素深度，\(K_v\) 为相机内参。

此时有三种情况：

- 两侧指向近似相同的三维位置：产生跨视角的对应一致性证据。
- 只有一侧可靠可见：使用该侧证据，另一侧不强行否定。
- 两侧都声称匹配成功但三维位置明显冲突：保留竞争假设并降低置信度，不能简单平均位置。

必须以源 Anchor ID 为单位融合证据。同一个 Anchor 被左右重复观察时，不应被当作两个独立的物体结构约束。

### B. Grounding 同时考虑 Sim(3) 与有约束的 Affine

针对不同尺寸的 Shelf/Drawer，不能始终强求一个全局 Sim(3)。

建议候选几何假设包含：

\[ T_{\mathrm{sim}}(\mathbf p)=sR\mathbf p+\mathbf t \]

以及：

\[ T_{\mathrm{affine}}(\mathbf p)=A\mathbf p+\mathbf t \]

其中 \(s\) 是统一尺度，\(R\) 是旋转矩阵，\(A\) 是允许非均匀伸缩的矩阵，\(\mathbf t\) 是平移向量。

但 Affine 不能无限制使用。需要要求锚点具有足够三维分布、矩阵条件数合理、变形幅度符合物体形状相似性假设，以及匹配残差能够被独立对应点验证。

如果来源于抽屉边缘的对应点不足以约束完整三维仿射变换，就不能输出一个看似精确的仿射结果。

这里的 Affine 只负责跨实例的参考位置定位，不负责缩放方块或复制源区域。

对于目标与源几何非常相似的情况，Sim(3) 更简单，应该有更高的模型优先级；当有充分证据证明非均匀伸缩存在时，才采用有约束的 Affine。

### C. 可见性必须区分 Positive、Negative、Unknown

这是多视角方案真正优于纯 MARCO 匹配的重要地方。

将候选三维点投影到某侧相机，比较候选深度 \(z_q\) 与实际深度图测量 \(d_v\)。

| 观测情况                           | 含义             | 如何处理 |
| ---------------------------------- | ---------------- | -------- |
| 深度一致、SAM 物体点有效           | 表面得到观测支持 | Positive |
| 测得更近的物体遮挡了候选位置       | 候选点不可见     | Unknown  |
| 候选位置位于可靠测量到的自由空间内 | 与观测几何矛盾   | Negative |
| 超出视场、无效深度、深度边缘不确定 | 无法判断         | Unknown  |

这是深度几何意义上的分类，并不是 MARCO 的匹配相似度分类。

例如左侧相机能看到 Drawer 底面，右侧相机看到前挡板。右侧看不到底面不应使正确候选被拒绝，因为它属于 occluded，不是 free space。

这里深度一致性容差需要包含深度测量误差、外参标定误差和几何定位误差。双相机不准时，硬性三维一致性反而会误杀正确匹配。

我还单独运行了可见性单元测试，验证了：同深度支持、前景遮挡中性、自由空间矛盾、无效深度中性。这四种状态在代码中具有不同处理。

### D. 最后输出交互偏好，而不是复刻区域

联合 Grounding 输出目标参考中心 \(\mathbf c_t^*\)、候选模式和定位不确定性。

随后根据新场景的可见支撑表面及方块真实尺寸生成放置候选：

\[ p(\mathbf q)\propto \exp\left( -\frac12 (\mathbf q-\mathbf c_t^*)^\top \Sigma_m^{-1} (\mathbf q-\mathbf c_t^*) \right) \mathbf 1[\mathbf q\in\mathcal C_{\mathrm{valid}}] \]

其中：

- \(\mathbf q\)：目标候选放置位置的局部平面坐标。
- \(\Sigma_m\)：以真实米制尺寸定义的采样协方差。
- \(\mathcal C_{\mathrm{valid}}\)：由目标支撑面、方块接触投影、已观测碰撞和操作可达性约束产生的有效集合。
- \(\mathbf 1[\cdot]\)：可行时取 1，否则为 0。

这样 Drawer 变宽时，参考中心可以根据结构关系迁移，但采样尺度不会随着 Drawer 宽度自动放大。

左右双视角点云融合的另一个实际价值，就是能获得更完整的可见支撑表面，从而更可靠地计算 \(\mathcal C_{\mathrm{valid}}\)。

必须用完整 RGB-D 深度参与障碍检查，而不只是 SAM 筛出的 Drawer 点云。未观测空间仍应标记为未知，不能默认没有障碍。

## 4. 正式系统应该有哪些拒绝条件？

不能要求算法在任意输入下都返回唯一正确的位置。我建议输出明确的状态，而不是只给一个参考点和未经校准的置信度。

| 状态                       | 触发条件                                             |
| -------------------------- | ---------------------------------------------------- |
| `OK`                       | 跨实例对应可靠，目标接触几何得到支持，有可行放置候选 |
| `AMBIGUOUS`                | 不同位置存在多个近似同样合理的 Grounding 假设        |
| `INSUFFICIENT_OBSERVATION` | 两个视角都无法观察目标必要的接触几何                 |
| `CALIBRATION_INVALID`      | 双相机共有几何存在异常大的一致性误差                 |
| `NO_FEASIBLE_PLACEMENT`    | 找到结构参考位置，但方块没有可验证的可行放置位置     |

对于关闭的 Cabinet 或未拉出的 Drawer，如果内部接触面完全不可见，不能强行通过视觉匹配预测内部的一个精确可行区域。

这不影响 Multi-view Grounding 的设计，只是把“打开后观测”的功能状态作为必要输入条件。

## 5. 对真实 MARCO 数据，怎样验证这套完整设计？

仿真证明的是机制可以运行。真实部署必须使用你的 MARCO 特征和 RGB-D 数据检验，尤其要测试当前仿真没有覆盖充分的情况。

我建议保留以下严格对照：

| 消融实验                                | 要回答的问题                               |
| --------------------------------------- | ------------------------------------------ |
| Right Only                              | 同侧视觉对应到底有多强？                   |
| Best View Selection                     | 两个视角中选择一个是否已经足够？           |
| Naive Correspondence Pooling            | 不处理重复与矛盾证据是否有害？             |
| Joint Sim(3)                            | 双视角是否主要解决遮挡与外点？             |
| Joint Bounded Affine                    | 非均匀尺寸变化能否通过几何对应处理？       |
| Joint Grounding + Visibility + Relation | 是否真正提升交互任务成功率与错误拒绝能力？ |

真实验证时，不能只评估单点 Grounding 误差。因为我们已经确认区域是偏好，不是一个必须精确复刻的目标。

最终应该关注正确功能位置命中率、Top-K 实际可行放置率、错误接受率、拒绝率、完整端到端 P50/P95 耗时。同时单独记录两侧相机相对源演示的角度变化、遮挡率、外参误差和目标几何比例变化。

特别是仿真的非均匀变形由已知仿射关系生成，因此它天然有利于仿射估计；98.4% 不能被解释成真实 Shelf/Drawer 的预期成功率。当前几何求解器的耗时优势也不代表双视角 MARCO 总耗时一定低于单视角，必须把两个视觉 backbone 的推理时间计入。

## 我的最终判断

我赞成你把 Multi-view Grounding 正式放在 Transfer 阶段，而不是把它做成源描述子的一部分。

我甚至认为它让整个方法的职责划分更清晰：

源示教负责表达交互意图，MARCO 负责产生可能的跨实例对应，多视角 Grounding 负责确定这些对应在目标三维空间中是否互相支持，接触几何负责决定最终在哪里能放置。

因此我会将方法定义为：

Multi-view Geometric Grounding of Object-relative Interaction Priors

它的核心不是构造一个更强的多视角 Descriptor，而是在只有单视角示教的条件下，利用运行期所有可用观测，为交互参考位置建立鲁棒的多假设三维证据。

这次执行的仿真支持这个方向，也揭示了它的关键边界：双视角联合比直接选一个视角有更多可利用信息，但只有在正确处理跨实例形变、错误对应和可见性后，这些额外信息才可能稳定转化为更好的 Grounding。
